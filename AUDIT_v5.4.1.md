# WARSTATE v5.4.1 release-candidate audit

Повторный аудит после v5.4.0. Это не утверждение, что в любой среде физически невозможно встретить новый баг; документ фиксирует обнаруженные и устранённые дефекты и локально проверенные инварианты.

## Исправлено

- Canvas terrain-cache: добавлен явный null fallback, устраняющий strict TypeScript build blocker и небезопасный путь восстановления контекста.
- Приватные группы админ-панели снова работают только через запрос владельцу/администратору и Telegram Reply. Автоматическое создание invite-link удалено.
- Старые bot-minted admin invite rows (`request_message_id = 0`) отменяются миграцией 041.
- Все найденные Supabase write/read операции в app/lib теперь явно проверяют `{ error }`; убраны ложные `try/catch`, которые не ловили PostgREST errors.
- ЧП и анархия больше не закрываются как успешно применённые, если RPC потерь упал: состояние откатывается для повторной обработки.
- Cooldown теперь fail-closed: ошибка БД не отключает антиспам.
- Humanitarian timestamp выставляется и при попадании ровно на резерв 50.
- Нельзя купить активный Инструмент I поверх Инструмента II и потерять монеты/прогресс.
- Нельзя купить равный или более низкий дворянский титул поверх уже имеющегося.
- Добавлены проверки отсутствующего игрока/гражданства в endgame RPC.
- Исправлен устаревший текст: анархия начинается через 2 часа, а Казна защищена гуманитарным резервом, а не «уходит в минус».
- `!сдать` явно запрещён в Нейтральной зоне.
- `.env.example` синхронизирован с реальными слотами ЧП 08:00 / 13:00 / 18:00.
- Проектный аудит усилен защитными регрессионными проверками для этих дефектов.

## Обязательная миграция

После 040 применить `supabase/migrations/041_release_candidate_audit.sql`.

## Проверки

- `npm run audit:project`
- TypeScript parser на всех TS/TSX
- strict semantic scan с локальными заглушками внешних модулей: нет структурных TS18047/TS2304/TS2339/TS2451 и аналогичных ошибок проекта
- AST scan Supabase calls: нет обнаруженных `await` запросов без обработки `{ error }` в `app`/`lib`
- SQL static checks и RPC signature audit
- archive integrity check

Полный `next build` требует реальных npm-зависимостей и отдельно отмечается только если он действительно выполнен.
